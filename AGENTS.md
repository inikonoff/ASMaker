# ASMaker — правила для ИИ-помощников и разработчиков

ASMaker — браузерный конструктор рекламных стендов: белая основа из ПВХ с прозрачными карманами на скотче. Им пользуются на реальных заказах цеха, поэтому главное — не сломать работающее и не потерять данные пользователя. Сайт: https://inikonoff.github.io/ASMaker/

Интерфейс, тексты, комментарии в коде, сообщения коммитов и CHANGELOG — на русском. Отвечая владельцу проекта, объясняйте простыми словами: он ставит задачи и проверяет результат в браузере, но код сам не пишет.

## Устройство

- **Один исходник: `src/app.html`** (HTML, CSS и весь JavaScript, ~6300 строк). Фреймворков и сборщика нет, функции объявлены глобально.
- **`python3 tools/build.py`** собирает `index.html`: встраивает шрифты (Fontsource через npm) и qrcode-generator, дописывает отпечаток исходника. **`index.html` правится только сборкой**, и после каждой правки `src/app.html` его нужно пересобрать и закоммитить вместе с исходником. Иначе упадёт `tests/test_build.py`.
- **Ориентиры в `src/app.html`** (ищите по имени):

| Что | Где |
|---|---|
| Модель документа | `newDoc`, `make*` (makePocket, makeText, …), `MAKERS` |
| Проверка входа | `normalizeObj`, `normalize` |
| Пересчёт размеров | `syncDerived` |
| Правка и история | `mutate`, `commit`, `undo`, `redo` |
| Отрисовка холста | `invalidate` → `flush` → `renderScene` / `renderOverlay` / `renderLayers` / `renderProps` |
| Разметка элемента | `objMarkup(o, exp)`, `*Markup` |
| Экспорт | `exportSVG`, `renderStand`, `encodeExport`, `makePDF`, `runWorkPack`, `exportDrawing` |
| Панель свойств | `build<Тип>(o)` из `sec`, `row`, `cap`, `sliderField`, `colorField`, `bind`/`bindFn`; вкладки — `TABS`, `SEC_TAB` |
| Сохранение | `serialize`, `saveNow` (localStorage), `libSave` (библиотека в IndexedDB), `assetDB` (картинки), облако Google Диска |
| Что нового | `WHATS_NEW` в начале скрипта, `CHANGELOG.md` |

- **Документ:** `doc = { version, title, pricing, grid, groups, objects, theme?, vars? }`. `objects[0]` — всегда основа (`type: 'base'`). Варианты макета: активный лежит в `doc.objects`, остальные — в `doc.vars.store`; для обхода всех используйте `allObjects()`.
- **Картинки** лежат в словаре `assets` (id → data URL, оригинал). На холст они идут blob-ссылкой `assetUrl(id)`; большие фото заменяются экранной копией до 2560 px. В экспорт и файлы идёт оригинал `assets[id]`. Выбирает `assetHref(id, exp)`. В IndexedDB каждая картинка пишется один раз (`persistAssets`), в localStorage — только проект без картинок.

## Обязательные правила

1. **Новое поле элемента** добавляется в трёх местах: значение по умолчанию в `make*`, проверка с умолчанием в `normalizeObj` (старые проекты и файлы его не содержат), `STYLE_KEYS`, если это стиль. Формат файла `.stand.json` должен читаться старыми и новыми версиями.
2. **Любое изменение документа — через `mutate(key, fn)`.** Так работают отмена и автосохранение. `key` склеивает частые правки одного поля (ввод, ползунок) в один шаг отмены.
3. **Разметка с `exp = true`** идёт в экспорт и печать. В ней только оригиналы картинок и встроенные шрифты, никаких blob-ссылок. На холсте (`exp = false`) — наоборот: blob-ссылки, а не base64.
4. **Скорость.** Не перестраивайте целиком то, что можно обновить точечно: сцена кэширует узлы по `objSig`, список слоёв — строки по ключу. Тяжёлое (превью, уменьшение фото) — в простое (`idle()`) и через `createImageBitmap`. Не кладите мегабайтные строки в DOM и в localStorage.
5. **Данные пользователя не терять.** Ничего не удаляйте из IndexedDB и библиотеки без явного действия пользователя. Исключение — `gcAssets`, она удаляет только картинки, на которые не ссылается ни один проект.
6. **Каждое заметное изменение** записывается в `WHATS_NEW` (новая запись сверху, новый ключ `v`) и в `CHANGELOG.md` (сверху). Новые разделы интерфейса — в `README.md`.
7. **Ошибка, найденная пользователем, получает тест**, который на старой версии падает, а на новой проходит.

## Проверка перед коммитом

```bash
python3 tools/build.py
pip install -r tests/requirements.txt && python -m playwright install chromium   # один раз
python -m pytest tests -q
```

Тесты открывают `index.html` в Chromium и падают на любой ошибке в консоли страницы. Обвязка в `tests/conftest.py`: фикстура `app` — чистая вкладка, `profile` — постоянный профиль (перезапуск вкладки, IndexedDB). Код страницы выполняется через `app.js('...')`. Две ловушки:
- если выражение возвращает функцию, Playwright её вызовет;
- если оно возвращает промис, тест будет ждать его, в том числе ответа в окне подтверждения `ask()`. Для таких вызовов пишите `void f()`.

На GitHub тесты запускает `.github/workflows/pages.yml`, и он же публикует сайт только из `main` и только после зелёных тестов.

## Чего не делать

- Не переводить проект на фреймворк и не дробить файл без отдельного решения владельца.
- Не менять ключи Google (`GOOGLE`) и `privacy.html` без запроса: от них зависит вход и проверка приложения в Google.
- Не менять ключи хранилища (`STORE`, имена баз и хранилищ IndexedDB). Иначе у пользователей «пропадут» проекты.
